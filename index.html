Artificial repair sample: ids[] → ids


This fixture is ours, not a customer case. A deliberate contract change is illustrated below; the preflight does not apply it.


Before: matching handler required
properties: { "ids[]": { type: "array", ... } }
required: ["ids[]"]
handler reads args["ids[]"]
After: handler AND callers must change
properties: { "ids": { type: "array", ... } }
required: ["ids"]
handler reads args.ids


Local fixture tests preserve ID order and duplicates: [7, 2, 7] produces the same items from both handlers. That is a handler equivalence check, not evidence of target-client compatibility.


Before using any patch: review the real handler, update argument-producing callers, and run a concrete target-client test. Root anyOf/oneOf are not rewritten merely because they are present.
